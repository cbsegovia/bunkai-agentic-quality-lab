# ATC Spec: BK-1101 - Open-bugs read rejects callers without a valid credential or atc:read

> Ticket: BK-1101 (BK-258 TC9, ROI 6.3, High)
> Component: OpenBugsApi (`tests/components/api/OpenBugsApi.ts`, new)
> Type: API - Negative (+ allowed contrast rows)
> Parent Story: BK-258

## 1. Test Case Summary

| Name | Objective | Precondition | Acceptance Criteria |
|------|-----------|--------------|---------------------|
| `expectAccessDecision` | The workspace aggregate is readable only with a valid session or a PAT holding `atc:read` | Owner account, active workspace id, credential minted per row | Risk beyond AC (authorization): no credential / invalid bearer -> 401 `unauthorized`; PAT without `atc:read` -> 403 "Missing required capability: atc:read"; PAT with `atc:read` or cookie -> 200 |

## 2. ATC Contract

```typescript
export type AccessExpectation =
  | { status: 401, code: 'unauthorized' }
  | { status: 403, code: 'forbidden', message: string | RegExp }   // code confirmed by spike S2
  | { status: 200 };

/**
 * ATC: The open-bugs read for a workspace, called with whatever credential is
 * currently set on this component, answers the expected decision.
 *
 * Fixed assertions:
 *  - response status equals expected.status
 *  - denied (401/403): envelope carries ONLY `error` (no open_count / by_severity
 *    leak), error.code matches, 403 message matches
 *  - allowed (200): body has integer open_count and by_severity.P1..P4
 */
@atc('BK-1101')
async expectAccessDecision(
  args: { workspaceId: string, expected: AccessExpectation },
): Promise<[APIResponse, OpenBugs | ErrorEnvelope]>
```

The credential is NOT a parameter: the test sets it on the component (`api.setAuthToken` / `api.clearAuthToken`, same convention as `TraceabilityApi.expectUnauthenticatedRejection`). Keeping the credential outside the signature keeps the ATC at one object param and lets the data rows own the credential set-up.

## 4. Assertions Split

### Fixed (inside ATC)

- `response.status() === expected.status`
- 401/403: `Object.keys(body)` equals `['error']` (non-disclosure: no count keys), `body.error.code === expected.code`
- 403: `body.error.message` matches `expected.message`
- 200: `Number.isInteger(body.open_count)`; `by_severity` has exactly P1..P4 integer values

### Test-level (in test file)

- Which credential each row uses and how it is created / revoked (the decision table).
