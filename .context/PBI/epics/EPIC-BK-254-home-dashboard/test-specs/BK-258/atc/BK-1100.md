# ATC Spec: BK-1100 - Open-bugs API contract and cross-credential parity

> Ticket: BK-1100 (BK-258 TC8, ROI 3.0, High)
> Component: OpenBugsApi (`tests/components/api/OpenBugsApi.ts`, new)
> Type: API - Verification (contract)
> Parent Story: BK-258 (AC1, API contract)

## 1. Test Case Summary

| Name | Objective | Precondition | Acceptance Criteria |
|------|-----------|--------------|---------------------|
| `expectOpenBugsContract` | A workspace member gets a well-formed, self-consistent open-bugs payload, identical whichever accepted credential is used | Owner account is a member of `{workspaceId}`; the credential of the row is set on the component | AC1 (API contract): 200; `open_count` integer; `by_severity` with keys P1-P4; `open_statuses` = `["open","in_progress"]`; `open_count` = sum of `by_severity`; values identical across credentials |

Scope note: the Jira TC also lists "values equal the Home card" and "equal a DB count (when DB access exists)". The card parity is asserted by BK-1093 (same oracle read). The DB leg is out of scope: no DB access (`DBHUB_*` mostly empty). Absolute-number correctness is therefore proven by BK-1093's seeded deltas, not by this contract ATC.

## 2. ATC Contract

```typescript
/**
 * ATC: Read the workspace open-bugs summary with the credential currently set
 * on this component - expects 200 and a self-consistent body.
 *
 * Fixed assertions:
 *  - status 200
 *  - open_count is an integer >= 0
 *  - by_severity has EXACTLY the keys P1,P2,P3,P4, each an integer >= 0
 *  - open_count === P1 + P2 + P3 + P4
 *  - open_statuses deep-equals ['open', 'in_progress']
 */
@atc('BK-1100')
async expectOpenBugsContract(workspaceId: string): Promise<[APIResponse, OpenBugs]>
```

## 4. Assertions Split

### Fixed (inside ATC)

The list in section 2.

### Test-level (in test file)

- The three returned bodies are deep-equal (values identical across credential types).
- Row order: default PAT, minted PAT, cookie last (the signin that creates the cookie pollutes the test's cookie jar; rows 1-2 must run on a cookie-free context).

## 5. Code Template

```typescript
import { test, expect } from '@TestFixture';
import { config } from '@variables';

test.describe('BK-258: Open-bugs API contract', { tag: ['@regression'] }, () => {
  test('BK-1100: should return open_count and by_severity with the same values when a workspace member calls the open-bugs API with each accepted credential', async ({ api }) => {
    const [, me] = await api.auth.getCurrentUser();
    const workspaceId = me.active_workspace_id!;
    const pat = await api.auth.mintScopedPat({ scopes: ['atc:read'] });
    try {
      const [, byDefaultPat] = await api.openBugs.expectOpenBugsContract(workspaceId);
      api.setAuthToken(pat.token);
      const [, byMintedPat] = await api.openBugs.expectOpenBugsContract(workspaceId);
      await api.auth.authenticateSuccessfully(config.testUser);   // sets cookie (+ bearer)
      api.clearAuthToken();                                        // cookie only
      const [, byCookie] = await api.openBugs.expectOpenBugsContract(workspaceId);
      expect(byMintedPat).toEqual(byDefaultPat);
      expect(byCookie).toEqual(byDefaultPat);
    } finally {
      await pat.revoke();
    }
  });
});
```

## 8. Data Context

| Precondition | Pattern | Source | Placement | Cleanup |
|--------------|---------|--------|-----------|---------|
| Workspace the caller belongs to | Discover | `getCurrentUser()` | test body | none |
| Minted `atc:read` PAT | Generate | `mintScopedPat` | test body | `pat.revoke()` in `finally` |
| Cookie session | Generate | signin in the test's own context | test body, LAST | context disposed at test end |

Flake risk: the three reads happen within a second or two on a shared workspace; a concurrent bug created by another session in that window would break the "identical values" assertion. Mitigation if it ever bites: re-read the first credential after the third and require each body to equal the baseline OR the re-read.
